## クイックスタート

次のどれかを、プロフィール用の `README.md`（ユーザー名と同じ名前のリポジトリ）に貼り付けてください。

```markdown

![A random cat](https://readmes.pages.dev/ascii/cat)
![Today's 2channel classic](https://readmes.pages.dev/ascii/2ch/daily)
```

中央揃えにしたいときや、いくつか横に並べたいときは HTML を使います。


### タグについて

kawaii タグには、やわらかく明るい顔を集めています。クマ、きつね、振る手、眠そうなほっぺ。親しみやすく少し遊び心のあるプロフィールに向いています。

cat タグは猫好きのためのタグです。欧米風のアスキーアートの猫の顔と日本の猫の顔文字、そして 2ちゃんねるで有名な不機嫌な猫、ギコ猫が入っています。

2ch タグは日本のテキスト掲示板の定番です。2ちゃんねる（現在の 5ちゃんねる）では、AA と呼ばれるアスキーアートの文化がまるごと育ちました。モナーやギコ猫のようなキャラクターはマスコットになり、オワタ、キタ、orz といった短い顔は、今も日本の SNS で使われる日常的なスラングになりました。

reddit タグには、Reddit のコメント欄の定番になった顔を集めています。肩をすくめる顔、不満げな視線、レニーフェイスなどです。いくつかは別の場所で生まれ、Reddit でいちばん広く知られるようになりました。

4chan タグは、グリーンテキストという語り方とドヤ顔です。無害で職場でも見られるものだけを入れています。

yami タグは、かわいさと暗さを混ぜた日本のスタイル「病みかわいい」から来ています。ここでは穏やかな悲しみだけを指します。雨、涙、うるうるのぴえん顔、眠気です。自傷に触れるものはコレクションに一切含まれていません。

meme タグはほかのいくつかと重なっていて、ほとんどの人がひと目でわかるものを集めています。

## 顔文字の短い歴史

掲示板が生まれたころから、人はキーボードの文字で顔を描いてきました。`:-)` のような欧米のエモーティコンは、頭を左に傾けて横向きに読みます。日本の顔文字はそれとは別に育ち、正面から読みます。この小さな違いが、まったく異なる 2 つの伝統を形づくりました。

顔文字は読み手のほうを向いているので、目と口が感情を表します。`(^_^)` は穏やかで楽しげ、`(;_;)` は泣き顔、`(ﾟДﾟ)` は驚き顔です。日本のコンピューターには最初から全角文字やカタカナ、多くの記号がありました。書き手はそれらを自由に組み合わせ、腕や汗や輝きや小道具のついた顔を作りました。

1990 年代後半から 2000 年代の日本のテキスト掲示板、とくに 2ちゃんねるで、これはアスキーアートを略した AA という本格的な表現形式に育ちました。常連たちはモナーやギコ猫のようなキャラクターを何行にもわたって描き、回し合い、手を加え、決めぜりふを与えました。そうした掲示板の短い顔は日常の言葉になりました。オワタは「終わった」、キタは「来た」という意味です。ひざまずく人の形をした orz は、完全な敗北を表します。

それらの顔の多くは、のちに英語圏のサイトへ渡りました。ちゃぶ台返しは日本の掲示板から伝わり、いら立ちを表す定番の反応になりました。肩をすくめる顔は、カタカナの「ツ」を顔として借りています。不満げな視線の顔は、細めた目にカンナダ文字を使っています。レニーフェイスは 4chan でばらばらの Unicode 文字から組み立てられ、その後 Reddit に広まりました。

グリーンテキストも同じ仲間です。4chan では `>` で始まる行が緑色になり、人々は `>be me` で始めて 1 行ずつ短い話を語るようになりました。この形式は今では、生まれたサイトをはるかに越えて知られています。

このコレクションでは、README にきれいに収まるよう、どれも 1 行から 3 行と短くしています。そして、元の作品が暗に示していた小さな動きを加えました。まばたき、手振り、ジャンプ、打ち込まれる 1 行です。

## プロフィールでの使い方のアイデア

名前の近くに小さなものを 1 つ置くと、署名のように働きます。眠そうな顔やまばたきする猫のような静かなものなら、プロジェクトから注意をそらさずに親しみやすい雰囲気を作れます。

2〜3 個を横に並べたヘッダーは、プロフィールに個性を与えます。動くものと止まったものを組み合わせると、ページがうるさくなりません。

毎日変わるモードは、プロフィールに生きている感じを出したい人に向いています。好みに合うタグを選んで `daily` を付ければ、日によって違うものが表示されます。

長い README の区切りにも使えます。「Projects」の上に 1 つ、「Contact」の上にもう 1 つ置けば、ページにメリハリが出ます。

プロフィールにテーマがあるなら、それに合わせましょう。暗いプロフィールに rainbow オプションを使うと楽しげになり、アクセントカラーに合わせた単色にすると整った印象になります。

## オプション

オプションは `/ascii/` の後ろに続くパスの部分で、順番は自由です。末尾に `.svg` を付けてもよく、大文字と小文字は区別しません。書き間違えると、画像の代わりに不明なオプションの位置を示すピンク色の小さな通知が出ます。

### 何を表示するか

| オプション | 効果 |
|---|---|
| 表の名前 | そのセット |
| `kawaii`、`meme`、`cat`、`yami`、`reddit`、`4chan`、`2ch` | そのタグからランダムに 1 つ |
| `random` | すべての中からランダムに 1 つ（既定） |
| `daily` | 1 日 1 つ。タグと組み合わせることもできます |

### 見た目

| オプション | 効果 |
|---|---|
| `size-N`、`size-Nrem` | 文字サイズ（ピクセル）、12 から 64（既定 22） |
| `px` | rem ではなく正確なピクセルに固定（下記参照） |
| `card` | 背景に角丸のカード |
| `border-N` | カードの枠線（ピクセル）、0 から 8 |
| `color-RRGGBB` | 文字色（16 進数、`#` なし） |
| `rainbow` | 文字がやわらかな色にゆっくり変わる |
| `auto`、`light`、`dark`、`transparent` | テーマ（既定は `auto`） |
| `warm` | GitHub と同じ文字色（既定）の代わりに、readmes の温かみのある配色を使う |
| `left`、`center` | 揃え方の指定 |

### 動き

| オプション | 効果 |
|---|---|
| `speed-N` | 再生速度（パーセント）、25 から 400 |
| `bounce` | 全体がふわふわと上下に揺れる |
| `static` | 最初のコマだけで、アニメーションなし |

auto モードでは、明るい背景には暗い文字、暗い背景には明るい文字になり、見る人の GitHub のテーマに合わせます。グリーンテキストは、色を指定しない限り伝統的な緑のままです。

### rem でのサイズ指定

どの画像も rem でサイズが決まっていて、1rem は 16 ピクセルです。ブラウザーの既定の設定では、ピクセル指定とまったく同じに見えます。文字を読みやすくするためにブラウザーの既定の文字サイズを大きくしている人には、周りの文字と同じように画像も大きくなります。`size-2rem` のように rem でサイズを書くこともできます。同じ行の他の画像と揃えたいときなど、正確なピクセルのサイズを保ちたい場合は `px` を付けてください。

## しくみ

各セットは、テキストのコマとそれぞれの表示時間の短いリストとして保存されています。URL を開くと、小さな Cloudflare Pages Function がそのリストを SVG に変換します。各コマはテキスト行のグループになり、数行の CSS がグループを順番に表示したり隠したりします。

アニメーションは画像の中の純粋な CSS なので、画像を表示できる場所ならどこでも再生されます。GitHub の画像プロキシはそれをそのまま通し、プロフィール上でスクリプトが動くことはありません。

文字はピクセルに変換されず、SVG の中で本物の文字のまま残ります。そのためファイルはとても小さく、多くは 2 KB を大きく下回り、色もライトモードとダークモードに合わせられます。

### なぜ GIF ではなく SVG なのか

README に動きを入れるには動く GIF が一般的ですが、テキストアートにはあまり向きません。GIF はすべてのコマをピクセルで保存するので、小さな顔でも数十 KB になります。色が固定なのでダークモードにも合わせられません。高解像度の画面では文字がぼやけたり、ギザギザになったりします。

テキストの SVG なら、この 3 つの問題をすべて避けられます。ファイルには文字と数行のタイミングしか入っていないので、どれだけ大きく描いても小さいままです。ブラウザーが本物のフォントで文字をくっきり描きます。色は見る人のテーマに合わせられ、サイズや速度や色は別のファイルを書き出すのではなく、URL の一部として変えられます。

ひとつだけトレードオフがあります。GIF はどこでも同じに見えますが、SVG の文字は各端末にあるフォントに左右されます。短い顔文字ではほとんど問題になりませんが、だからこそこのコレクションは、正確な位置合わせが必要な大きな複数行の絵を避けています。

### フォントと位置揃え

アートは見る人の端末の等幅フォントで描かれます。ほとんどのシステムには日本語の文字に対応した等幅フォントがあるので、顔はほぼどこでも正しく見えます。それでもフォントによって間隔が少し違うことがあり、とくにモナーのような複数行の作品の全角記号で目立ちます。歩く猫やグリーンテキストのように横に動くものは、きっちり揃うよう半角の ASCII だけで作っています。

キャンバスはわざと少し余裕を持たせた大きさにしてあるので、見る人のフォントが思ったより幅広くても、アートが切れることはありません。

### キャッシュ

名前を固定した URL は 1 日キャッシュされるので、すぐに表示されます。ランダムな URL はキャッシュを無効にして返すので、GitHub はたいてい表示のたびに新しいものを取りに来ます。毎日変わる URL は UTC の 0 時までキャッシュされ、そのあと切り替わります。

## アクセシビリティ

各画像には「ASCII art: Owata (animated)」のようなタイトルが付いています。埋め込むときは代替テキストも付けてください。上の例のとおりです。アートは本物の文字なので、スクリーンリーダーが文字そのものを読み上げることもあります。たいていは害はありませんが、奇妙に聞こえることがあるので、わかりやすい代替テキストを付ける理由がもう 1 つ増えます。

システム設定で「視差効果を減らす」などの動きを減らす設定をオンにしている人には、アニメーションが止まり、最初のコマが静止画として表示されます。`static` オプションを使うと、すべての人に同じ表示になります。

既定の色は、GitHub の明るい背景と暗い背景のどちらに対しても WCAG AA のコントラストを満たしています。自分で色を選ぶ場合は、両方のテーマで読みやすいか確認してください。

## 自分のアートを追加する

デモは設計上、アップロードや自由なテキストを受け付けません。自分のセットを追加するには、自分のコピーを動かしてください。Cloudflare Pages なら無料で、数分で済みます。

必要なのは Node.js 20 以降、`make`、そして無料の Cloudflare アカウントです。依存パッケージがないので `npm install` はありません。

1. GitHub で「Use this template」を押してリポジトリを作り、クローンします。
2. `site.config.json` に自分の名前とリポジトリのリンクを入れます。
3. 既存のものにならって `src/ascii/arts.js` に項目を追加します。
4. `make test` を実行し、デプロイします。

```sh
npx wrangler pages project create my-badges --production-branch production
make deploy PROJECT=my-badges
```

これでアートは `https://my-badges.pages.dev/ascii/<name>` で表示されます。

### セットの書き方

セットには、URL 用の名前、タイトル、1 つ以上のタグ、そしてコマのリストが必要です。各コマは 1 行から 3 行のリストです。すべてのコマ共通の表示時間をミリ秒で 1 つ指定するか、コマごとの表示時間のリストを指定します。

```js
{ name: "my-cat", title: "My cat", tags: ["cat"], d: [1500, 200],
  frames: [["(=^-^=)"], ["(=-.-=)"]] },
```

短い間はまばたきになり、長めに止めると目が休まります。横に動くものは `align: "left"` を指定し、空白を使った半角の ASCII だけで作れば、どのフォントでも歩幅が揃います。ファイルの先頭にある 2 つの補助関数で、タイピングと歩行のアニメーションを作れます。

テストでは、名前が重複していないこと、コマが 1 行から 3 行であることを確かめます。さらに、すべてのセットがエラーなく描画できること、どのコマにも絵文字が含まれていないことも確認します。絵文字フォントは等幅の見た目を崩してしまうからです。

### プロジェクトの構成

```
functions/ascii/        Pages Functions：アート、ヘルプページ、エージェント向けページ
src/ascii/arts.js       コレクション（アートを追加するときはここを編集）
src/ascii/options.js    URL オプションの解析
src/ascii/render.js     SVG と CSS アニメーション
src/ascii/handler.js    リクエスト処理とキャッシュ
src/ascii/pages.js      ギャラリー、URL ビルダー、エージェント向けガイド
test/                   node:test の単体テスト
```

すべて `ascii` のパスの下にあるので、このプロジェクトはファイル名をぶつけることなく、他のバッジアプリと 1 つの Pages プロジェクトを共有できます。

## よくある質問

### スマートフォンだと少し違って見えるのはなぜ？

端末ごとに自分のフォントで文字を描くので、幅や形が少しずつ違います。作品はそれに耐えられるものを選んでいますが、全角記号の位置が少しずれることはあります。

### URL に自分の文章を書けますか？

いいえ。自由なテキストを受け付けると、誰でもこのサイトから配信される画像に好きな言葉を載せられてしまうので、デモは自分のコレクションしか知りません。自分のデプロイには、アートのリストに追加したものを何でも入れられます。

### プロフィールのランダムなアートが変わらない

ブラウザーが古いコピーを持っているのかもしれません。強制再読み込みを試すか、キャッシュに左右されない、決まった日替わりの `daily` を使ってください。

### GitHub 以外でも使えますか？

## トラブルシューティング

### 画像がピンク色の「unknown option」通知になる

パスのどこかが、既知の名前でもオプションでもありません。通知は `/ascii/` の後ろから数えたその位置を教えてくれます。ギャラリーとオプション一覧でつづりを確認してください。名前は `table-flip` のようにハイフンでつなぎます。

### アートの端が切れる

どの画像にも余裕を持たせているので、めったに起きません。それでも、とても幅広い代替フォントでは起きることがあります。`size-N` で少し大きくすると、比率を保ったまま余白が増えます。`card` オプションでも余白が加わります。

### アニメーションが動かない

システムで動きを減らす設定がオンになっていないか確認してください。オンの場合は、意図的に最初のコマが表示されます。エディターの Markdown プレビューの中には、SVG の最初のコマしか表示しないものもあります。GitHub の実際のプロフィールページではアニメーションが再生されます。

### ダークモードで色がおかしい

`color-RRGGBB` で色を固定すると、どちらのテーマでも同じ色のままです。外せば文字が見る人のテーマに合わせて変わります。あるいは、明るい背景と暗い背景のどちらでも読みやすい中間の色を選んでください。

## プライバシー

デモは何も保存しません。アップロード、フォーム、Cookie、アクセス解析はありません。各画像は URL のパスだけから計算され、受け付けるのは決まったオプションの一覧だけです。

GitHub では画像は GitHub のプロキシ経由で取得されるので、デモはふつうプロフィールを見ている人の IP アドレスを知ることはありません。どの Web サイトとも同じく、Cloudflare は独自の[プライバシーポリシー](https://www.cloudflare.com/privacypolicy/)に従って標準的なリクエストのログを保持することがあります。
