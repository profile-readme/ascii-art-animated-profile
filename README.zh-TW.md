## 快速開始

把下面任意一行貼到你的個人首頁 `README.md`（與使用者名稱同名的儲存庫）中：

```markdown
![Owata](https://readmes.pages.dev/ascii/owata)
![A random cat](https://readmes.pages.dev/ascii/cat)
![Today's 2channel classic](https://readmes.pages.dev/ascii/2ch/daily)
```

第一行一律顯示 Owata。第二行每次開啟頁面都會顯示一隻隨機的貓。第三行每天挑選一個 2channel 經典，所以你什麼都不用做，首頁每天都會變化。

如果想置中，或把幾個並排放在一起，可以使用 HTML：

```html
<p align="center">
  <img src="https://readmes.pages.dev/ascii/kitsune/card" alt="小狐狸">
  <img src="https://readmes.pages.dev/ascii/suya/card" alt="想睡的臉">
</p>
```

### 關於標籤

kawaii 標籤收集柔和、開朗的表情：熊、狐狸、揮動的小手、想睡的臉頰。適合想要顯得友善又帶點俏皮的首頁。

cat 標籤獻給愛貓的人。它混合了西式的 ASCII 貓臉、日式的貓顏文字，還有 2channel 上以脾氣差出名的 Giko 貓。

2ch 標籤收錄日本文字討論板的經典。2channel（現在叫 5channel）孕育出一整套稱為 AA 的 ASCII 藝術文化。Mona 和 Giko 這樣的角色成了吉祥物，而 Owata、Kita、orz 這樣的短小表情則成了至今仍在日本社群媒體上使用的日常用語。

reddit 標籤收集在 Reddit 留言區成為常客的表情，例如聳肩、不滿的眼神和 Lenny 臉。其中幾個起源於別處，卻在 Reddit 上找到了最廣大的受眾。

4chan 標籤包括 greentext 這種說故事的格式和得意臉。只收錄無害、適合在工作場合觀看的作品。

yami 標籤來自「病態可愛」（yami kawaii），一種把可愛與陰鬱混合在一起的日本風格。在這裡它只代表溫和的憂傷：雨、眼淚、淚汪汪的 pien 臉和睏意。收藏中沒有任何內容涉及自我傷害。

meme 標籤與其他幾個標籤有所重疊，收集的是大多數人一眼就能認出的作品。

## 文字表情簡史

自從有了留言板，人們就開始用鍵盤字元畫臉。像 `:-)` 這樣的西式表情是橫著讀的，要把頭往左歪。日式顏文字則是另外發展起來的，正面閱讀。這個小小的差異塑造了兩種截然不同的傳統。

因為顏文字是正對著讀者的，眼睛和嘴巴承載了情緒。`(^_^)` 平靜而開心，`(;_;)` 在哭，`(ﾟДﾟ)` 很震驚。日本的電腦從一開始就提供全形字元、片假名和大量符號。作者們自由地組合它們，畫出帶著手臂、汗珠、閃光和道具的臉。

在 1990 年代末到 2000 年代的日本文字討論板上，尤其是 2channel，這發展成一種完整的藝術形式，稱為 AA，也就是 ASCII art 的縮寫。常客們用許多行畫出 Mona 和 Giko 這樣的角色，互相傳播、修改，還替它們配上口頭禪。這些討論板上的短小表情變成了日常用語。Owata 的意思是「完了」，Kita 的意思是「來了」。跪倒在地的小人 orz 代表徹底的失敗。

其中許多表情後來流傳到英語網站。翻桌來自日本討論板，成了表達挫折的標準反應。聳肩借用了片假名「ツ」當作臉。不滿的眼神用卡納達文字母當作瞇起的眼睛。Lenny 臉是在 4chan 上用零散的 Unicode 字元拼湊出來的，之後傳遍了 Reddit。

greentext 也屬於同一個家族。在 4chan 上，以 `>` 開頭的行會變成綠色，人們開始以 `>be me` 開頭，一行一行地講短故事。如今這種格式早已遠遠超出它誕生的網站。

這個收藏讓每件作品都保持簡短，只有 1 到 3 行，好整齊地放進 README。它還加入了原作只是暗示的小動作：眨眼、揮手、跳一下，或打出一行字。

## 首頁使用靈感

在名字旁邊放一件小作品，就像一個簽名。像想睡的臉或眨眼的貓這樣安靜的作品，能營造友善的氛圍，又不會搶走專案的注意力。

把兩三件作品並排成一列頁首，能為首頁增添個性。把一件動態作品和一件靜態作品搭配起來，頁面就不會顯得雜亂。

每日模式適合希望首頁顯得有生氣的人。挑一個合你口味的標籤，加上 `daily`，不同日子來的訪客就會看到不同的作品。

作品也可以用來替長 README 分段。在 "Projects" 上面放一個，在 "Contact" 上面再放一個，頁面就有了節奏感。

如果你的首頁有主題，就配合它。深色首頁配上 rainbow 選項顯得活潑，而與強調色一致的單色看起來整潔又用心。

## 選項

選項是寫在 `/ascii/` 之後的路徑片段，順序不拘。結尾可以加 `.svg`，不區分大小寫。如果寫錯了，圖片會變成一個粉紅色的小提示，指出未知選項的位置。

### 要顯示什麼

| 選項 | 效果 |
|---|---|
| 表格中的名稱 | 那一套作品 |
| `kawaii`、`meme`、`cat`、`yami`、`reddit`、`4chan`、`2ch` | 從該標籤中隨機選一套 |
| `random` | 從全部作品中隨機選一套（預設） |
| `daily` | 每天一套，可以和標籤組合使用 |

### 外觀

| 選項 | 效果 |
|---|---|
| `size-N`、`size-Nrem` | 字體大小（像素），12 到 64（預設 22） |
| `px` | 固定為精確像素而非 rem（見下文） |
| `card` | 在作品後面加一張圓角卡片 |
| `border-N` | 卡片邊框（像素），0 到 8 |
| `color-RRGGBB` | 十六進位文字顏色，不含 `#` |
| `rainbow` | 文字在柔和的顏色之間慢慢變化 |
| `auto`、`light`、`dark`、`transparent` | 主題（預設 `auto`） |
| `warm` | 使用 readmes 的暖色配色，而非 GitHub 本身的文字顏色（預設） |
| `left`、`center` | 指定對齊方式 |

### 動態

| 選項 | 效果 |
|---|---|
| `speed-N` | 播放速度（百分比），25 到 400 |
| `bounce` | 整件作品輕輕上下浮動 |
| `static` | 只顯示第一格，不播放動畫 |

在 auto 模式下，淺色背景上文字是深色的，深色背景上文字是淺色的，與每位訪客的 GitHub 主題一致。除非你指定顏色，greentext 會保持傳統的綠色。

### 以 rem 為單位的尺寸

每張圖片都以 rem 為單位設定尺寸，1rem 等於 16 像素。在瀏覽器預設設定下，它看起來和像素尺寸完全相同。當讀者為了更容易閱讀而調大瀏覽器的預設字體大小時，作品也會像周圍的文字一樣跟著放大。你也可以直接用 rem 撰寫尺寸，例如 `size-2rem`。如果作品必須維持精確的像素尺寸，例如要和同一列的其他圖片對齊，請加上 `px`。

## 運作原理

每套作品都以一份簡短的文字畫格清單儲存，每一格都有自己的顯示時間。開啟 URL 時，一個小小的 Cloudflare Pages Function 會把這份清單轉換成 SVG。每一格變成一組文字行，幾行 CSS 依序顯示和隱藏這些群組。

因為動畫是圖片內部的純 CSS，所以在任何能顯示圖片的地方都能播放。GitHub 的圖片代理會原封不動地放行，你的首頁上不會執行任何指令碼。

文字在 SVG 中保持為真正的文字，而不是被轉成像素。這讓檔案非常小，通常遠小於 2 KB，顏色也能跟隨淺色和深色模式。

### 為什麼用 SVG 而不是 GIF

動態 GIF 是在 README 中加入動畫的常見做法，但它並不適合文字藝術。GIF 把每一格都存成像素，就算是一張小小的臉也會有幾十 KB。它的顏色是固定的，所以無法配合深色模式。在高解析度螢幕上，文字會變得模糊或出現鋸齒。

文字 SVG 避開了這三個問題。檔案裡只有字元和幾行時間設定，所以無論畫多大都很小。瀏覽器用真正的字型把文字繪製得清晰銳利。顏色可以跟隨訪客的主題，尺寸、速度和顏色只是 URL 的一部分，不需要匯出不同的檔案。

只有一個取捨。GIF 在哪裡看都一樣，而 SVG 中的文字取決於每台裝置上可用的字型。對於短小的顏文字來說這幾乎沒有影響，這也正是本收藏避開需要精確對齊的大型多行畫作的原因。

### 字型與對齊

作品使用訪客裝置上的等寬字型繪製。大多數系統都有支援日文字元的等寬字型，所以這些臉幾乎在任何地方都能正確顯示。不同字型之間的間距仍可能略有差異，尤其是在 Mona 這類多行作品的全形符號上。會橫向移動的作品，例如走路的貓和 greentext，都只用純 ASCII 製作，所以能精確對齊。

畫布特意留了一點餘裕，就算訪客的字型比預期更寬，作品也不會被截斷。

### 快取

名稱固定的 URL 會快取一天，所以能立即載入。隨機 URL 回傳時關閉快取，因此 GitHub 在大多數情況下每次都會取得新的作品。每日 URL 快取到 UTC 午夜，然後更換。

## 無障礙

每張圖片都有類似 "ASCII art: Owata (animated)" 的標題，嵌入時你也應該加上替代文字，就像上面的範例那樣。因為作品是真正的文字，螢幕閱讀器可能也會唸出這些字元。這通常無害，但聽起來可能有點奇怪，這也是要寫清楚替代文字的另一個理由。

在系統設定中開啟了「減少動態效果」的人，動畫會停止，看到的是第一格的靜態圖片。`static` 選項會讓所有人都看到同樣的效果。

預設顏色在 GitHub 的淺色和深色背景上都符合 WCAG AA 對比度。如果你自己挑選顏色，請確認它在兩種主題下都清晰可讀。

## 加入你自己的作品

展示依設計不接受上傳或自訂文字。如果想加入你自己的作品，請執行你自己的副本。在 Cloudflare Pages 上是免費的，幾分鐘就能完成。

你需要 Node.js 20 或更新版本、`make`，以及一個免費的 Cloudflare 帳號。專案沒有任何相依套件，所以不需要 `npm install`。

1. 在 GitHub 上點選 "Use this template"，建立你的儲存庫並複製（clone）它。
2. 在 `site.config.json` 中填入你自己的名字和儲存庫連結。
3. 參照現有的項目，在 `src/ascii/arts.js` 中加入新項目。
4. 執行 `make test`，然後部署。

```sh
npx wrangler pages project create my-badges --production-branch production
make deploy PROJECT=my-badges
```

之後你的作品就會在 `https://my-badges.pages.dev/ascii/<name>` 提供。

### 撰寫一套作品

一套作品需要一個用於 URL 的名稱、一個標題、一個或多個標籤，以及一份畫格清單。每一格是 1 到 3 行的清單。你可以為所有畫格指定一個以毫秒為單位的統一時間，也可以為每一格分別指定時間。

```js
{ name: "my-cat", title: "My cat", tags: ["cat"], d: [1500, 200],
  frames: [["(=^-^=)"], ["(=-.-=)"]] },
```

短暫的停頓形成眨眼，較長的停留讓眼睛得到休息。對於橫向移動的作品，請設定 `align: "left"`，並只用帶空格的純 ASCII 製作，這樣每種字型的步幅都會一致。檔案開頭的兩個輔助函式可以幫你產生打字和行走動畫。

測試會檢查名稱是否唯一、每一格是否為 1 到 3 行。測試也會檢查每套作品都能無錯誤地繪製，並且沒有任何一格包含 emoji，因為 emoji 字型會破壞等寬的效果。

### 專案結構

```
functions/ascii/        Pages Functions：作品、說明頁、給 AI 代理的頁面
src/ascii/arts.js       收藏（加入作品時編輯這裡）
src/ascii/options.js    URL 選項解析
src/ascii/render.js     SVG 與 CSS 動畫
src/ascii/handler.js    請求處理與快取
src/ascii/pages.js      圖庫、URL 產生器、代理指南
test/                   node:test 單元測試
```

所有內容都位於 `ascii` 路徑下，所以這個專案可以和其他徽章應用程式共用一個 Pages 專案，而不會發生檔名衝突。

## 常見問題

### 為什麼在手機上看起來有點不一樣？

每台裝置都用自己的字型繪製文字，所以寬度和形狀會略有不同。收錄的作品都經過挑選，能承受這種差異，但全形符號的位置可能會稍有偏移。

### 我可以在 URL 中寫自己的文字嗎？

不可以。如果接受自由文字，任何人都能在本站提供的圖片上放任意文字，所以展示只認得自己的收藏。你自己的部署可以包含你加入作品清單的任何內容。

### 我首頁上的隨機作品一直不變

可能是你的瀏覽器保留了舊的副本。試試強制重新整理，或使用不受快取影響、依固定規律每日更換的 `daily`。

### 在 GitHub 以外也能用嗎？

可以。任何能顯示圖片 URL 的地方都能用，包括個人網站、其他程式碼託管平台和論壇簽名檔。

### 我可以為展示推薦新作品嗎？

## 疑難排解

### 圖片顯示粉紅色的 "unknown option" 提示

某個路徑片段既不是已知的名稱，也不是選項。提示會告訴你它的位置，從 `/ascii/` 之後的第一個片段開始數。請對照圖庫和選項表檢查拼字；名稱用連字號連接，例如 `table-flip`。

### 作品的邊緣被截斷了

這種情況很少見，因為每張圖片都留有餘裕。但遇到特別寬的備用字型時仍可能發生。用 `size-N` 把作品稍微調大，可以在維持比例的同時獲得更多空間，`card` 選項也會增加額外的內距。

### 動畫不會動

檢查你的系統是否開啟了「減少動態效果」。如果開啟了，會刻意顯示第一格。編輯器裡的某些 Markdown 預覽也只顯示 SVG 的第一格。GitHub 上真正的個人首頁會播放動畫。

### 深色模式下顏色看起來不對

如果用 `color-RRGGBB` 固定了顏色，它在兩種主題下都會保持不變。拿掉它，文字就會跟隨訪客的主題；或者選擇一個在淺色和深色背景上都清晰可讀的中間色。
