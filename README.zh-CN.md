## 快速开始

把下面任意一行粘贴到你的个人主页 `README.md`（与用户名同名的仓库）中：

```markdown
![Owata](https://readmes.pages.dev/ascii/owata)
![A random cat](https://readmes.pages.dev/ascii/cat)
![Today's 2channel classic](https://readmes.pages.dev/ascii/2ch/daily)
```

第一行总是显示 Owata。第二行每次打开页面都会显示一只随机的猫。第三行每天挑选一个 2channel 经典，所以你什么都不用做，主页每天都会变化。

如果想居中，或者把几个并排放在一起，可以使用 HTML：

```html
<p align="center">
  <img src="https://readmes.pages.dev/ascii/kitsune/card" alt="小狐狸">
  <img src="https://readmes.pages.dev/ascii/suya/card" alt="困倦的脸">
</p>
```

### 关于标签

kawaii 标签收集柔和、开朗的表情：熊、狐狸、挥动的小手、困倦的脸颊。适合想要显得友好又带点俏皮的主页。

cat 标签献给爱猫的人。它混合了西式的 ASCII 猫脸、日式的猫颜文字，还有 2channel 上以脾气差出名的 Giko 猫。

2ch 标签收录日本文字论坛的经典。2channel（现在叫 5channel）孕育出了一整套被称为 AA 的 ASCII 艺术文化。Mona 和 Giko 这样的角色成了吉祥物，而 Owata、Kita、orz 这样的短小表情变成了至今仍在日本社交媒体上使用的日常俚语。

reddit 标签收集在 Reddit 评论区成为常客的表情，比如耸肩、不满的眼神和 Lenny 脸。其中几个起源于别处，却在 Reddit 上找到了最广泛的受众。

4chan 标签包括 greentext 这种讲故事的格式和得意脸。只收录无害、适合在工作场合查看的作品。

yami 标签来自"病态可爱"（yami kawaii），一种把可爱与阴郁混合在一起的日本风格。在这里它只代表温和的忧伤：雨、眼泪、泪汪汪的 pien 脸和困意。收藏中没有任何内容涉及自我伤害。

meme 标签与其他几个标签有重叠，收集的是大多数人一眼就能认出的作品。

## 文字表情简史

自从有了留言板，人们就开始用键盘字符画脸。像 `:-)` 这样的西式表情是横着读的，要把头向左歪。日式颜文字则是另外发展起来的，正面阅读。这个小小的差别塑造了两种截然不同的传统。

因为颜文字是正对着读者的，眼睛和嘴巴承载了情绪。`(^_^)` 平静而开心，`(;_;)` 在哭，`(ﾟДﾟ)` 很震惊。日本的电脑从一开始就提供全角字符、片假名和大量符号。作者们自由地组合它们，画出带着手臂、汗珠、闪光和道具的脸。

在 1990 年代末到 2000 年代的日本文字论坛上，尤其是 2channel，这发展成了一种完整的艺术形式，叫做 AA，也就是 ASCII art 的缩写。常客们用很多行画出 Mona 和 Giko 这样的角色，互相传播、修改，还给它们配上口头禅。这些论坛上的短小表情变成了日常用语。Owata 的意思是"完了"，Kita 的意思是"来了"。跪倒在地的小人 orz 代表彻底的失败。

其中很多表情后来流传到了英语网站。掀桌来自日本论坛，成了表达沮丧的标准反应。耸肩借用了片假名"ツ"当作脸。不满的眼神用卡纳达文字母当作眯起的眼睛。Lenny 脸是在 4chan 上用零散的 Unicode 字符拼出来的，之后传遍了 Reddit。

greentext 也属于同一个家族。在 4chan 上，以 `>` 开头的行会变成绿色，人们开始以 `>be me` 开头，一行一行地讲短故事。如今这种格式早已远远超出了它诞生的网站。

这个收藏让每件作品都保持简短，只有 1 到 3 行，好整齐地放进 README。它还加入了原作只是暗示的小动作：眨眼、挥手、跳一下，或者打出一行字。

## 主页使用灵感

在名字旁边放一件小作品，就像一个签名。像困倦的脸或眨眼的猫这样安静的作品，能营造友好的氛围，又不会抢走项目的注意力。

把两三件作品并排放成一行页眉，能给主页增添个性。把一件动态作品和一件静态作品搭配起来，页面就不会显得杂乱。

每日模式适合希望主页显得有生气的人。挑一个合你口味的标签，加上 `daily`，不同日子来的访客就会看到不同的作品。

作品也可以用来给长 README 分节。在 "Projects" 上面放一个，在 "Contact" 上面再放一个，页面就有了节奏感。

如果你的主页有主题，就配合它。深色主页配上 rainbow 选项显得活泼，而与强调色一致的单色看起来整洁又用心。

## 选项

选项是写在 `/ascii/` 之后的路径片段，顺序任意。末尾可以加 `.svg`，不区分大小写。如果写错了，图片会变成一个粉色的小提示，指出未知选项的位置。

### 显示什么

| 选项 | 效果 |
|---|---|
| 表格中的名称 | 那一套作品 |
| `kawaii`、`meme`、`cat`、`yami`、`reddit`、`4chan`、`2ch` | 从该标签中随机选一套 |
| `random` | 从全部作品中随机选一套（默认） |
| `daily` | 每天一套，可以和标签组合使用 |

### 外观

| 选项 | 效果 |
|---|---|
| `size-N`、`size-Nrem` | 字号（像素），12 到 64（默认 22） |
| `px` | 固定为精确像素而不是 rem（见下文） |
| `card` | 在作品后面加一张圆角卡片 |
| `border-N` | 卡片边框（像素），0 到 8 |
| `color-RRGGBB` | 十六进制文字颜色，不带 `#` |
| `rainbow` | 文字在柔和的颜色之间慢慢变化 |
| `auto`、`light`、`dark`、`transparent` | 主题（默认 `auto`） |
| `warm` | 使用 readmes 的暖色配色，而不是 GitHub 自身的文字颜色（默认） |
| `left`、`center` | 指定对齐方式 |

### 动态

| 选项 | 效果 |
|---|---|
| `speed-N` | 播放速度（百分比），25 到 400 |
| `bounce` | 整件作品轻轻上下浮动 |
| `static` | 只显示第一帧，不播放动画 |

在 auto 模式下，浅色背景上文字是深色的，深色背景上文字是浅色的，与每位访客的 GitHub 主题一致。除非你指定颜色，greentext 会保持传统的绿色。

### 以 rem 为单位的尺寸

每张图片都以 rem 为单位设定尺寸，1rem 等于 16 像素。在浏览器默认设置下，它看起来和像素尺寸完全一样。当读者为了更容易阅读而调大了浏览器的默认字号时，作品也会像周围的文字一样随之放大。你也可以直接用 rem 书写尺寸，例如 `size-2rem`。如果作品必须保持精确的像素尺寸，比如要和同一行的其他图片对齐，请加上 `px`。

## 工作原理

每套作品都以一份简短的文字帧列表保存，每一帧都有自己的显示时长。打开 URL 时，一个小小的 Cloudflare Pages Function 会把这份列表转换成 SVG。每一帧变成一组文字行，几行 CSS 依次显示和隐藏这些组。

因为动画是图片内部的纯 CSS，所以在任何能显示图片的地方都能播放。GitHub 的图片代理会原样放行，你的主页上不会运行任何脚本。

文字在 SVG 中保持为真正的文字，而不是被转成像素。这让文件非常小，通常远小于 2 KB，颜色也能跟随浅色和深色模式。

### 为什么用 SVG 而不是 GIF

动态 GIF 是在 README 中加入动画的常见做法，但它并不适合文字艺术。GIF 把每一帧都存成像素，哪怕是一张小小的脸也会有几十 KB。它的颜色是固定的，所以无法适应深色模式。在高分辨率屏幕上，文字会变得模糊或出现锯齿。

文字 SVG 避开了这三个问题。文件里只有字符和几行时间设置，所以无论画多大都很小。浏览器用真正的字体把文字渲染得清晰锐利。颜色可以跟随访客的主题，尺寸、速度和颜色只是 URL 的一部分，而不需要导出不同的文件。

只有一个取舍。GIF 在哪里看都一样，而 SVG 中的文字取决于每台设备上可用的字体。对于短小的颜文字来说这几乎没有影响，这也正是本收藏避开需要精确对齐的大型多行画作的原因。

### 字体与对齐

作品使用访客设备上的等宽字体绘制。大多数系统都有支持日文字符的等宽字体，所以这些脸几乎在任何地方都显示正确。不同字体之间的间距仍可能略有差异，尤其是在 Mona 这类多行作品的全角符号上。会横向移动的作品，比如走路的猫和 greentext，都只用纯 ASCII 制作，所以能精确对齐。

画布特意留出了一点余量，即使访客的字体比预期更宽，作品也不会被截断。

### 缓存

名称固定的 URL 会缓存一天，所以能立即加载。随机 URL 返回时关闭缓存，因此 GitHub 在大多数情况下每次都会取新的作品。每日 URL 缓存到 UTC 午夜，然后更换。

## 无障碍

每张图片都有类似 "ASCII art: Owata (animated)" 的标题，嵌入时你也应该加上替代文本，就像上面的示例那样。因为作品是真正的文字，屏幕阅读器可能也会读出这些字符。这通常无害，但听起来可能有些奇怪，这也是要写清楚替代文本的另一个理由。

在系统设置中开启了"减少动态效果"的人，动画会停止，看到的是第一帧的静态图片。`static` 选项会让所有人都看到同样的效果。

默认颜色在 GitHub 的浅色和深色背景上都满足 WCAG AA 对比度。如果你自己挑选颜色，请确认它在两种主题下都清晰可读。

## 添加你自己的作品

演示按设计不接受上传或自定义文字。如果想添加你自己的作品，请运行你自己的副本。在 Cloudflare Pages 上是免费的，几分钟就能搞定。

你需要 Node.js 20 或更新版本、`make`，以及一个免费的 Cloudflare 账户。项目没有任何依赖，所以不需要 `npm install`。

1. 在 GitHub 上点击 "Use this template"，创建你的仓库并克隆它。
2. 在 `site.config.json` 中填入你自己的名字和仓库链接。
3. 参照已有的条目，在 `src/ascii/arts.js` 中添加新条目。
4. 运行 `make test`，然后部署。

```sh
npx wrangler pages project create my-badges --production-branch production
make deploy PROJECT=my-badges
```

之后你的作品就会在 `https://my-badges.pages.dev/ascii/<name>` 提供。

### 编写一套作品

一套作品需要一个用于 URL 的名称、一个标题、一个或多个标签，以及一份帧列表。每一帧是 1 到 3 行的列表。你可以为所有帧指定一个以毫秒为单位的统一时长，也可以为每一帧分别指定时长。

```js
{ name: "my-cat", title: "My cat", tags: ["cat"], d: [1500, 200],
  frames: [["(=^-^=)"], ["(=-.-=)"]] },
```

短暂的停顿形成眨眼，较长的停留让眼睛得到休息。对于横向移动的作品，请设置 `align: "left"`，并只用带空格的纯 ASCII 制作，这样每种字体的步幅都会一致。文件开头的两个辅助函数可以帮你生成打字和行走动画。

测试会检查名称是否唯一、每一帧是否为 1 到 3 行。测试还会检查每套作品都能无错误地渲染，并且没有任何一帧包含 emoji，因为 emoji 字体会破坏等宽的效果。

### 项目结构

```
functions/ascii/        Pages Functions：作品、帮助页、给 AI 代理的页面
src/ascii/arts.js       收藏（添加作品时编辑这里）
src/ascii/options.js    URL 选项解析
src/ascii/render.js     SVG 与 CSS 动画
src/ascii/handler.js    请求处理与缓存
src/ascii/pages.js      图库、URL 生成器、代理指南
test/                   node:test 单元测试
```

所有内容都位于 `ascii` 路径下，所以这个项目可以和其他徽章应用共用一个 Pages 项目，而不会出现文件名冲突。

## 常见问题

### 为什么在手机上看起来有点不一样？

每台设备都用自己的字体绘制文字，所以宽度和形状会略有不同。收录的作品都经过挑选，能经得起这种差异，但全角符号的位置可能会稍有偏移。

### 我可以在 URL 中写自己的文字吗？

不可以。如果接受自由文本，任何人都能在本站提供的图片上放任意文字，所以演示只认识自己的收藏。你自己的部署可以包含你添加到作品列表里的任何内容。

### 我主页上的随机作品一直不变

可能是你的浏览器保留了旧的副本。试试强制刷新，或者使用不受缓存影响、按固定规律每日更换的 `daily`。

### 在 GitHub 以外也能用吗？

可以。任何能显示图片 URL 的地方都能用，包括个人网站、其他代码托管平台和论坛签名。

### 我可以为演示推荐新作品吗？

欢迎在仓库中以 issue 的形式提出建议。合适的作品应当简短、广为人知、适合在工作场合查看，并且能用普通等宽字体正常显示。以商业角色或品牌为基础的作品会被刻意排除，以免涉及商标问题。

### 使用这些颜文字可以吗？

它们是人们几十年来自由分享的民间艺术。本项目如何对待它们，请参阅许可证一节。

## 故障排除

### 图片显示粉色的 "unknown option" 提示

某个路径片段既不是已知的名称，也不是选项。提示会告诉你它的位置，从 `/ascii/` 之后的第一个片段开始数。请对照图库和选项表检查拼写；名称用连字符连接，例如 `table-flip`。

### 作品的边缘被截断了

这种情况很少见，因为每张图片都留有余量。但遇到特别宽的后备字体时仍可能发生。用 `size-N` 把作品稍微调大，可以在保持比例的同时获得更多空间，`card` 选项也会增加额外的内边距。

### 动画不动

检查你的系统是否开启了"减少动态效果"。如果开启了，会有意显示第一帧。编辑器里的某些 Markdown 预览也只显示 SVG 的第一帧。GitHub 上真正的个人主页会播放动画。

### 深色模式下颜色看起来不对

如果用 `color-RRGGBB` 固定了颜色，它在两种主题下都保持不变。去掉它，文字就会跟随访客的主题；或者选择一个在浅色和深色背景上都清晰可读的中间色。

## 隐私

演示不存储任何东西。没有上传、表单、Cookie 或分析。每张图片只根据 URL 路径计算，并且只接受固定的选项列表。

在 GitHub 上，图片是通过 GitHub 的代理获取的，所以演示通常看不到浏览你主页的人的 IP 地址。和任何网站一样，Cloudflare 可能会依据其自身的[隐私政策](https://www.cloudflare.com/privacypolicy/)保留标准的请求日志。
